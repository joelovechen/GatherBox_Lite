# 使用说明

[返回首页](../README.md)

## 开始使用

1. 从 Releases 下载安装包，或完整解压便携包。不要只复制其中的主程序 EXE。
2. 启动应用，在对应平台添加账号。部分内容需要登录或具备相应账号权限。
3. 选择视频、文章或回答，创建下载或归档任务。可在设置中调整下载位置、并发数和请求频率。
4. 遇到平台验证、限流或登录失效时，按提示处理，避免连续重复请求。

## 本地数据与备份

默认数据根目录为应用目录下的 `download/`；源码运行时位于项目根目录。设置中的“下载位置”控制媒体与归档输出位置，数据库仍属于应用数据根目录。

```text
download/
├── db/
│   ├── bilibili/bilibili.db
│   └── zhihu/
│       ├── zhihu_auth.db
│       └── accounts/
├── bilibili/           # 默认视频与音频输出
├── zhihu/              # 默认知乎归档输出
└── _updates/           # 更新包缓存
```

可在启动前设置 `BILI_DATA_DIR` 环境变量指定数据根目录。改变它不会自动复制原目录中的数据；请关闭应用后再备份、迁移，并确认新目录可写。

备份时先退出应用，再复制整个数据根目录；如果另设了下载位置，也应备份该位置。Windows 下凭据优先使用 DPAPI 加密，换电脑或 Windows 用户后可能需要重新登录。数据库和归档仍可能含个人信息，不应公开分享。

## 检查更新

在“关于与更新”中点击“检查更新”。应用优先读取 GitHub Releases，失败时尝试版本公告文件；发现新版本后显示版本号和更新说明。

- 有可用安装包直链时，可在应用内下载；下载完成后会尝试启动安装程序。
- “打开下载页面”在默认浏览器中打开发布链接。
- 公告没有安装包地址时，当前“下载并安装更新”也会转到网页，不会开始文件下载。
- 便携 ZIP 下载后会打开所在文件夹，应按该版本发布说明完成替换，不代表已自动安装。

更新检查和文件下载是两次独立网络请求。能看到更新说明，不代表安装包一定能下载成功；下载失败时可到发布页手动下载。当前下载器有第三方镜像回退逻辑，且未实现更新包数字签名验证。

更新或手动替换程序前，请备份数据，不要用空数据目录覆盖原目录。测试 Release 的标签可能与包内版本不同，以该 Release 的说明为准。

## 常见问题

| 问题 | 处理方式 |
|---|---|
| 窗口无法打开、提示缺少 WebView2 | 安装 Microsoft Edge WebView2 Runtime 后重试；在线引导安装需要网络 |
| 前端提示后端未连接 | 确认已完整解压，后端目录未被删除或拦截，并检查本地日志 |
| 视频或文章获取失败 | 检查账号状态、访问权限及平台验证提示；平台接口变化也可能导致失败 |
| 更新检查失败 | 稍后重试，或直接访问 GitHub Releases；失败不表示已经是最新版 |
| 修改下载位置后找不到旧文件 | 新设置不会自动搬迁既有媒体，先检查原下载位置 |

提交问题前请删除日志中的账号标识、Cookie、Token 和个人文件路径。
